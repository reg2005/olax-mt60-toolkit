# Kernel-only OTA without implicit unlock

2026-10-15, accepted implementation decision; hardware acceptance pending.
User requests a ZIP for stock web update on two new factory OLAX, with only the
kernel fix. Existing installed boot is validated only after explicit unlock.
Stock web calls RecoverySystem.installPackage and clears lrserver first. Stock
recovery/res/keys matches public AOSP testkey (RSA modulus/exponent). Package
acceptance does not prove locked bootloader will execute modified boot.

Deliver separate probe and guarded kernel ZIP. Probe writes no partitions, emits
non-secret compatibility facts in recovery log. Kernel ZIP is fail-closed on
locked/unknown boot state, unknown board/boot/recovery, inadequate power/backup.
Do not encode another modem's seccfg or add an unreviewed unlock. This means the
requested factory-locked one-step installation is NOT achieved by this version.
New hardware's probe/backup and a separate unlock/verified-boot plan are needed.

Only boot is a flash target; durable cache backup precedes it, verified readback
follows it. Write/readback failure triggers one bounded restoration attempt.
No power-cut/bootloop rollback is claimed. No web/addon/APK/settings are shipped;
OEM web cleanup before update remains an explicit side effect outside updater.

AOSP SHA1/testkey signing is required by this legacy recovery and is public;
it is not a new security design or our distribution identity. Package pins,
RSA/CMS verification and checksums support offline correctness, not hardware
proof. Gate public release on actual factory recovery, load, boot and recovery
acceptance. Keep shared private app-signing keys outside this pipeline.
