# ADR-0001: явные этапы и один переносимый CLI

Дата: 2026-10-15. Статус: принято для экспериментального 0.1.0.

Задача: повторяемая разблокировка одинаковых MT60 с трёх ОС с сохранением
идентификаторов и калибровок. Исходная процедура испытана на двух устройствах;
полный новый workflow и web OTA ещё не испытаны на заводском устройстве.

Выбран Python CLI и тонкие sh/PowerShell/cmd запускатели. Electron добавил бы
отдельный runtime и IPC вокруг того же USB-кода без устранения ручного power cycle.
Состояние хранится вне проекта. Enrollment закрепляет собственные резервные копии;
общий image seccfg никогда не распространяется.

Этапы: enroll → offline checks → RAM DA/crypto → one-sector transaction →
ручной power cycle → verify → stock web OTA → verify --kernel → close ADB.
Нет команд erase/format/relock и нет общего обхода защит.

Результат записи определяется полным readback, а не ACK. Journal записывается
атомарно с fsync до потенциальной записи. Повторное unlock после serviceStarted
запрещено, включая неоднозначный timeout. Прерванный process lock требует ручного
разбора, а не автоматического удаления.

POSIX может прервать блокирующий вызов SIGALRM и выполнить ограниченную оценку
состояния/rollback. Windows не имеет эквивалентного безопасного прерывания Python
main thread: таймер завершает дочерний процесс кодом124. Parent сохраняет UNKNOWN;
автоматический rollback при таком таймауте не выполняется. Эта потеря автоматического
восстановления предпочтительнее записи из потока с неизвестным состоянием USB.

Runtime mtkclient скачивается по commit+SHA256; все файлы package проверяются
перед сервисной операцией. Две локальные GPL-правки исправляют формат USB-фильтра.
AOSP public testkey загружается только для сборки OTA и не считается доказательством
авторства релиза. Hardware validation отслеживается отдельно от CI.

Пересмотреть GUI и модель подтверждений после аппаратной проверки на всех ОС
и наблюдения за несколькими самостоятельными установками.
