# Ошибки и восстановление

## Нельзя продолжать автоматически

`UNKNOWN`, `UNKNOWN_TIMEOUT`, `SERVICE_STOPPED` во время записи, неполный readback
или отсутствие финального отчёта означают неопределённый результат. Не повторяйте
unlock/restore, не удаляйте journal.json и `.operation-lock`, не загружайте наугад
другой образ. Если питание ещё есть, сохраните его до разбора результата.

Сохраните приватно `journal.json`, `ram-session/report.json`,
`unlock-result/report.json`, `*.log` и backup. Эти файлы могут содержать CID,
идентификаторы и сырые разделы — не прикладывайте их целиком в публичный issue.
Для issue достаточно версии toolkit, ОС, модели, названия этапа, кода ошибки,
состояния экрана и того, происходило ли отключение питания. Секреты/пароли не нужны.

`status --state PATH` показывает сводку без CID. После разрыва parent-процесса
может остаться `.operation-lock`: это преднамеренная блокировка повторной операции.
Удаление допустимо только после проверки, что дочерних USB-процессов больше нет
и понятно, какие операции могли успеть выполниться. Уже начатый unlock всё равно
не запустится повторно с этим journal.

Если ошибка произошла при enroll до любой сервисной записи, не используйте
неполную копию. После проверки соединения создайте отдельную новую папку для
повторного enroll, сохранив предыдущую для диагностики. После начала unlock
смена папки не является допустимым способом обхода защиты.

## Панель/ADB

Проверьте фактический IP, отсутствие VPN, пароль admin, подключение к сети именно
этого модема. Поддерживается только root ADB заводской ревизии. Скрипт не включает
root на произвольном Android и не обращается к Pixel по USB.

Штатный OTA-обработчик может удалить lrserver ещё до recovery. Если панель не
вернулась, её собственный архив сохранён как `backup/stock-ROOT.war.img` (это WAR,
суффикс .img только обозначает бинарную резервную копию). Не заменяйте его архивом
чужого модема и не распаковывайте только index/js. Восстановление требует полного
ROOT.war с WEB-INF и доступного root ADB; публичный toolkit не автоматизирует
восстановление веб-каталога при недоступном ADB. Нужен разбор конкретной загрузки.

## Возврат stock boot

Только после анализа журналов и подтверждения, что текущий boot целиком равен
известному исправленному образу. На Mac исходная реализация прошла offline-тесты;
возврат stock через новый переносимый wrapper аппаратно не принят.

```sh
./olax.sh restore --state "$HOME/.local/share/olax/unit01"
```

Windows: `olax.cmd restore --state "%LOCALAPPDATA%\OLAX\unit01"`.
После приглашения `RESTORE` подключите обесточенный перед этим модем с батареей
к USB. Скрипт повторно читает hardware/CID/GPT, проверяет собственные backup,
загружает закреплённый **штатный** DA в RAM и разрешает одну запись своего stock
boot. LK/preloader/NVRAM/seccfg не записываются. После полного readback нужно
перезапустить питание и выполнить `verify` без `--kernel`.

Если boot уже stock, записи нет. Если boot неизвестен или частично записан,
операция останавливается. Для такого случая универсального unbrick в комплекте
нет: требуется индивидуальный сервисный план. Автоматического relock нет,
возврат stock boot не возвращает исходное состояние загрузчика.

При любых работах с доступным Android завершайте диагностический доступ:
`close --host ROUTER_IP --state PATH`.
