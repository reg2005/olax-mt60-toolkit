# Причина нагрузки и состав патча

У исследованных t60_extchg_k61 в простое активно работали kernel threads
`pmic_thread` и `gauge_coulomb_t`. Разбор соответствующего образа показал две
инструкции, перезаписывающие Rfg отрицательным значением. Патч убирает эти записи
(ARM NOP); ранее измеренная нагрузка двух потоков после установки исчезла.
Это результат для конкретной прошивки, а не универсальный диагноз любого
перегрева MT60. Номинальная точность измерения тока/ёмкости этим не доказана.

| Адрес в распакованном ARM Image | Исходные байты | После |
|---|---|---|
| 0xc0a842c8 | 4c0087e5 | 0000a0e1 |
| 0xc0a8439c | 4c0087e5 | 0000a0e1 |
| 0xc0726a80 | 1f10a0e3 | 1210a0e3 |

Третья инструкция ограничивает длину таблицы внутреннего `mt6357_set_cv`:
максимальный используемый индекс17, 4 350 000 мкВ. Это ограничение внутреннего PMIC,
не доказательство управления внешним GPIO-зарядником. Полная зарядная политика
и калибровка индикатора батареи остаются отдельной задачей.

Весь stock boot закреплён SHA256 до использования адресов. Сжатое ядро сохраняет
исходный размер gzip-потока с помощью пустых DEFLATE-блоков, пересчитывается
legacy mkbootimg ID. Остальные байты, включая ramdisk и DTB, не меняются.
Рецепт: [ota/patch_boot.py](../ota/patch_boot.py).

После установки проверяйте полный boot SHA, uptime/reboot, дельту CPU времени
потоков (а не одно мгновенное значение top), доступность сети и работу экрана.
Не считайте проценты индикатора доказательством реальной ёмкости аккумулятора.
